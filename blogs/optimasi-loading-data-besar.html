Strategi Optimasi Query: Menangani Jutaan Data di Multi-Database & Ratusan Tabel

Khoirony Arief

July 13, 2026 • 5 min read

Sebagai seorang Backend Developer, salah satu tantangan paling mendebarkan adalah ketika aplikasi yang kita bangun mulai digunakan secara masif. Data membengkak, relasi antar tabel semakin rumit, dan tiba-tiba kecepatan loading aplikasi menurun drastis.

Baru-hari ini saya menangani arsitektur dengan skala yang lumayan menantang: 3 Database berbeda, di mana masing-masing database memiliki sekitar 50 tabel (Total 150 tabel) dengan jutaan baris data dan relasi antar-database. Jika kamu hanya menggunakan query standar Eloquent (ORM), sistem akan langsung crash atau timeout. Berikut adalah strategi tingkat lanjut yang saya gunakan.

1. Hindari "N+1 Problem" dengan Eager Loading Secara Ketat

Ini adalah dosa paling umum di Laravel. Ketika kamu me-looping data yang memiliki relasi, ORM akan melakukan query berulang kali. Jangan gunakan Lazy Loading saat mengambil data besar:

// ❌ BAD: Akan melakukan 1001 query jika ada 1000 user
$users = User::all();
foreach ($users as $user) {
    echo $user->profile->address;
}

// ✅ GOOD: Hanya melakukan 2 query
$users = User::with('profile')->get();
foreach ($users as $user) {
    echo $user->profile->address;
}

2. Drop Eloquent, Gunakan Query Builder untuk "Read-Only"

Eloquent ORM itu luar biasa untuk Create, Update, Delete. Tapi, ketika kamu harus menarik 50.000 data relasional hanya untuk ditampilkan ke dashboard, Eloquent akan memakan RAM sangat besar. Untuk read-only, gunakan DB Facade:

// Eksekusi jauh lebih ringan di memori
$data = DB::table('users')
    ->join('transactions', 'users.id', '=', 'transactions.user_id')
    ->select('users.name', 'transactions.amount')
    ->where('transactions.status', 'success')
    ->get();

3. Chunking & Cursor untuk Memori (OOM Prevention)

Saat harus mengekspor laporan dari 3 database dengan jutaan baris, jangan pernah gunakan ->get(). RAM VPS kamu pasti akan kehabisan napas. Gunakan chunk() atau cursor():

// Cursor hanya memuat 1 model tunggal ke dalam memori pada satu waktu
foreach (Transaction::cursor() as $transaction) {
    // Eksekusi sangat hemat RAM
}

4. Menangani Relasi Lintas Database

Kamu tidak bisa melakukan JOIN langsung jika tabel berada di database yang berbeda. Solusi ringannya adalah menggunakan WhereIn:

$users = DB::connection('db_users')->table('users')->where('status', 'active')->pluck('id');

// Bawa array ID tersebut ke database kedua
$transactions = DB::connection('db_transactions')->table('transactions')
    ->whereIn('user_id', $users)
    ->get();
